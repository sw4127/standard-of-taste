## THE STORE ALREADY EXISTED, AND THE BLUEPRINT DID NOT KNOW

`docs/blueprint-phase-2.md` and E12's activation prompt both describe G1 as "the store", as though
it had to be built. **It shipped in E8/S7.** Reading the code before planning changed the shape of
the whole track — G1 was not "build a store", it was two narrower things:

- The store deliberately kept **one session per instrument**, overwriting. `result-store.ts` said so
  in its own header: *"LAST SESSION WINS, deliberately… a history invites 'your best result'."*
  That reasoning is good and still binds, but it made the product's headline promise — *did your ear
  move* — impossible to keep, and it is why Track H could not start.
- The cooldown kept its **own key in its own format**, beside the store.

The risk the old design named is now handled where it belongs: **in a read API that cannot express
a ranking.** `readResult` answers "the latest", `readHistory` answers "all of them, oldest first",
neither can rank, and a test fails if a member named for a superlative ever appears in the module.

## FINDINGS THAT MUST NOT BE LOST

1. **A BREAK THAT DOES NOT FIRE IS A CLAIM TO CHECK, NOT A VERDICT.** One S3 break came back green
   and my first instinct was "the guard is weak". It was not — the blurb is a two-line
   concatenation and I had cut only the first half, leaving the fact intact. **My break was fake.**
   Had I accepted it I would have "strengthened" a guard that was already correct, and reported a
   false weakness. Re-run against the right line, it fails properly.

2. **A BYTE LENGTH STOPS BEING A CHANGE SIGNAL THE MOMENT A LIST IS CAPPED.** `AcrossSessions`
   detected "has anything been stored" by comparing each slot's byte length. At the cap, appending
   evicts the oldest — and for an instrument whose payloads are all the same width (the prestige
   test: sixteen single digits, thirteen-digit timestamps) **the envelope is the same size
   afterwards. Measured: 3716 before, 3716 after.** Another tab would have gone on rendering
   evicted sessions. Now `slotSignature()`, carrying count and newest timestamp.

3. **GATING A VALIDITY GATE ON A POOL VERSION WOULD HAVE FAILED IT OPEN ON DEPLOY DAY.** Every
   other read of the store drops sessions recorded against a different pool, correctly — positional
   answer tokens scored against a reordered pool answer different questions. Reuse that gated read
   for the cooldown and **a routine clip re-render unblocks every cooldown on the planet, silently.**
   `lastRecordedAt` is deliberately ungated: the answers stop being scoreable, the fact that someone
   sat through a session two days ago does not. The test was written before the code and watched to
   fail.

4. **THE BRACED-FORM RULE PAID TWICE MORE.** The disclosure guard asserted `ExpertPanel.tsx` renders
   `EXPERT_PANEL.blurb`; the file imports it under a local alias and renders `{PANEL.blurb}`. Keyed
   on the exported name, that assertion could never have passed — it would have failed forever for a
   reason unrelated to the fact it guards, which is how a guard trains people to disable it.

5. **A DISCOVERY SCAN BEATS A HAND-WRITTEN LIST, AND STILL CANNOT SEE EVERYTHING.** The disclosure
   guard fails when any component reads the store or the cooldown without being listed — proven by
   writing a throwaway component that prints *"Last time you scored 30%"* and watching the suite go
   red. **But it cannot see a surface that takes a recalled result as a PROP, or one that reads
   nothing** — `ForgetThisBrowser` had to be listed by hand for exactly that reason. The scan proves
   "no component reads undisclosed", not "no surface shows memory undisclosed".

6. **THE PRIVACY PAGE CARRIED TWO CLAIMS THAT WERE FALSE, NOT STALE**, on a page linked from the
   homepage footer, `/learn` and `/method`. It named **Stripe** as the payment processor when
   `paymentProvider()` has defaulted to **Dodo** since the merchant-of-record change, and named
   **Vercel Web Analytics alone** when `analytics.ts` has carried a second **PostHog** sink since E7.
   Found by checking each claim against the code — the claim I *expected* to be dead (artist names
   to Anthropic) turned out to be **true**, because the legacy funnel is live code. Three further
   "Stripe receipt" phrases outside the Privacy section were the same falsehood and are now
   provider-agnostic, since the payment adapter is.

7. **BACKTICKS IN A SHELL-RUN `node -e` ARE EATEN AS COMMAND SUBSTITUTION.** A template literal
   became `out.push({ surface: , text, … })` — a syntax error written into `voice.test.ts`. It
   failed loudly at parse time and was repaired with a literal tool. **The rule should now read:
   do not script file content through a shell at all when a literal tool will do.** "Assertions
   before the single write" does not help when the mangling is in the payload itself.

8. **HISTORY EXISTING IS NOT THE ARC, AND THE ROADMAP PREDICATE HAD TO KNOW THAT.**
   `published-text.test.ts` carried a comment saying Track G would create the artifact its unguarded
   "Retest arc" row was waiting for. It did — and a predicate keyed on "does a history store exist"
   would have flipped that row to **built**, making a public page claim a feature nobody can use.
   The predicate is **"something outside the store reads the history"**: false today, necessarily
   true the moment an arc ships. Test files are excluded, or the row would have flipped the day S1
   landed — **that exclusion is load-bearing and looks like tidying.**

9. **A PREDICATE IS ONLY SOUND WHILE ITS DOOR IS THE ONLY DOOR.** The store's export list is now
   pinned, because a second history accessor would let an arc ship while a public page called it
   planned with every test green.

10. **THE HIDDEN BROWSER PANE WILL NOT DISPATCH A POINTER CLICK.** `computer:left_click` refused the
    clear button, reporting its centre at `(-107, -512)`. `element.click()` from `javascript_tool`
    goes through React's event system identically and worked — but it does **not** prove the control
    is reachable by a real cursor or thumb, or that it is not visually clipped.

11. **THE S2 RED-TEAM FLAGGED A HOLE IN S4 BEFORE S4 EXISTED, AND IT WAS REAL.** The cooldown falls
    back to the retired `gym.lastCompleted.*` keys when the store is empty — which is exactly the
    state clearing produces. A sweep of `gym.result.*` alone would have left somebody **refused a
    retest forever, with the session behind the refusal deleted.** Pinned by a test and proven in a
    browser.
