This session opened by shipping five slices in one reply with the red-team batched at the end —
the exact failure `docs/slice-protocol.md` was written to kill. The cause was not judgment: CLAUDE.md
is in the system prompt for free and says the 7-step loop runs per TASK, while the amendment making
it run per SLICE lives in a file the session was told to read and never opened.

`.claude/hooks/slice-latch.py` now enforces it. **HEAD moving arms a latch**; file-modifying tools
are denied until the PM replies; read-only verification and `git push` still pass; the PM's
auto-advance grant disarms it. Every message puts §Session rhythm into context, read from the
protocol file itself.

**Three things it cost, so you do not rediscover them:**

1. **It armed on a MENTION at first.** A regression script holding the words "git commit" in a list
   of test cases armed it with nothing committed — and then denied the edit that would have fixed
   it, because the fix's own explanation has to name the phrase it triggers on. **A guard that
   matches text cannot be repaired through itself.** It asks git for HEAD now.
2. **`2>&1` was denied**, the commonest verification shape in this project, because `&` is a segment
   separator. Thirty-one synthetic cases had passed; every one was a clean one-liner written FOR the
   test rather than taken from the transcript.
3. **A broken hook fails silently and looks exactly like a permissive one.** The file was
   syntactically broken for one tool call and nothing surfaced an error.

It is machine-local (`.claude/settings.local.json` is gitignored), so a session on another machine
has the paragraph in `docs/slice-protocol.md` and nothing else.
