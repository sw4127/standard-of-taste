## FINDINGS THAT MUST NOT BE LOST

1. **READING THE RENDERED DECK BEAT EVERY TEST, THREE SLICES RUNNING.** S3: the "closer" and
   "further" fixtures both landed on the off-ladder branch, so the ordinary in-range sentence was
   never rendered anywhere — the assertion checked the DIRECTION, not which branch produced it.
   S5: the device note opened "Both sittings were read from this browser" directly beneath "One
   session cannot say whether your ear moved". S6: every reading still said "these two sittings"
   and "last time" after pooling made a reading rest on four. **All three suites were green.**

2. **NOTHING MAY COUNT — and this project keeps re-learning it in the same file.** Three separate
   arity defects in `src/content/vocabulary/arc.ts` in four slices. Guarded now: only the pooled
   line, which is handed the counts, may state a number.

3. **A SPACE NEXT TO AN HTML ENTITY VANISHES FROM THE RENDERED PAGE.** Eleven instances across
   five public pages ("yourblind ratings", "thatis a true judge", "entertainmentproduct"). **My
   first theory was wrong** — I assumed the JSX end-of-line whitespace rule, and a guard built on
   it would have caught almost none of them. Bisected to one character:
   `<em>that</em> is a judge. The Taste Gyms.` keeps the space; `...Gym&apos;s.` loses it. The
   trigger is the ENTITY, not the line break. Guard in `src/content/jsx-entity-space.test.ts`;
   fix is `{" "}` after the closing tag.

4. **THE ARC COMPARES A NUMBER THE RESULT SCREEN DOES NOT PRINT, DELIBERATELY.** `fitThreshold`
   refuses a point estimate on 21–77% of sessions, so comparing printed thresholds would select on
   the answer — the defect RT-90a(b) removed, re-entering through the arc. `fitPosterior`'s
   `logMedian` exists on **100%** of sessions. Consequently the staircase sentences report the size
   of a change as a MULTIPLE and never an endpoint, or the page would contradict itself (E8/S8).

5. **THE PRESTIGE HEADLINE IS A LATTICE, AND A QUANTILE CANNOT SEE ONE.** Raising the calibration
   quantile changed the false-positive rate by nothing at all — the same 6.6% to seven digits. The
   ratings are integers, so the achievable rates jump 6.6% → 3.4%. The floor is now the smallest
   cutoff clearing the target, which steps to the safe side of a lattice.

6. **A BREAK THAT DOES NOT FIRE IS A CLAIM TO CHECK — and twice this session the break was fake.**
   Two S3 breaks came back green because my `.replace()` needles contained a backtick that is not
   in the file, so nothing was edited. One S6 break "passed" because I grepped for `AssertionError`
   and it had failed as a `TypeError`. **The grep lied, not the guard.**

7. **THE TRANSPORT ATE A LEVEL OF ESCAPING, AGAIN.** A regex scripted through the shell as `\bx\b`
   wrote literal 0x08 BACKSPACE bytes into `arc.test.ts`; the pattern matched nothing and its own
   self-check failed. Sweep with `grep -rlP '\x08|\x01' src/` after ANY scripted write.

8. **HALF OF ALL COMPRESSION RETESTS USED TO BE UNCOMPARABLE.** The session seed is the clock, so
   two sittings landed on the same recording 49% of the time; the rest had to be refused, because a
   bitrate does up to 1.999x different damage across recordings. Measured end to end: **55% refused
   before the pin, 0% after.** The pin is derived from the stored session, not a new key — so
   "forget this browser" un-pins it for free.

9. **A CLAIM WRITTEN IN ONE SLICE WAS FALSIFIED BY THE NEXT.** S2's docblock said "half of all
   lossy retests land on a different recording… it is the ordinary outcome"; S4 made it the
