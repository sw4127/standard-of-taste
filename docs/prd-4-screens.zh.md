## 页面框架，每个页面都有

| | 实测 |
|---|---|
| 1280 px 下的容器 | **1024 px**（`max-w-5xl`），由 `src/app/shell-width.test.ts` 守住 |
| 375 px 下的容器 | 全宽，两侧各留 24 px |
| `/reading` 和 `/company` 上的阅读栏 | 1280 下 672 px；375 下 327 px |
| 没有横向滚动 | 下面每个界面，两种宽度下都没有 |

**框架共用，阅读栏不共用。** 曾经试过把正文加宽到 1024 px，后来撤回：它的排版比原先的窄栏差。

# 解读

## S-1 · 首页 `/`

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 标题 | 4 行 | 5 行 |
| 听者卡片 | 3 张，每行一张 | 3 张，每行一张 |
| 第一张卡片的上边缘 | 542 px | **684 px** |
| 听辨测试区 | 4 张测试卡片排成一行，然后是瑕疵链接 | 4 张测试卡片，每行一张 |

**访客在正文里第一个能操作的东西是一张听者卡片**（FR-8.2），两种宽度下它都在首屏之内。在手机上，它从 812 px 高的屏幕的 684 px 处开始：首屏里是标题、转向解读的那句话，以及一张卡片的顶部。页头放着公司视角、资料室、实验室和方法；页面自己的各区放着解读和听辨测试。

## S-2 · 解读 `/reading?l=…`

从首页点一次。以第一位听者 Mira 测量。

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 条目 | 4 | 4 |
| 第一条的上边缘 | 465 px | 700 px |
| 条目宽度 | 672 px | 327 px |

**每一条，从上到下：**规律 · 依据 · 「展开播放记录」 · 两种提示读法和「都不对」 · 「这条不对」。

**每一条的状态：**保留（默认） · 删去，此时提示读法被替换为「已删去。它不会进入你的提示词。」和「放回来」 · 已选读法 · 播放记录展开或收起。页面说明自己做什么的陈述，位于标题下方、第一条上方（FR-8.3）。

## S-3 · 提示词 `&step=prompt`

从首页点两次。

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 提示词，尚未反驳 | 10 行，成块显示 | 10 行，宽 327 px，自动换行，不横向滚动 |
| 桥梁标记，全新浏览器 | 0 | 0 |
| 操作 | 「复制」 · 「用听辨测试校准这些词」 · 「贴进 Tessavox」 | 同上 |

**对全新的浏览器，没有标记就是规定的状态**（FR-6.2）：标记只来自存储在设备上的阈值测试。选了某种读法之后，才会出现「情绪」一行（FR-4.3）；删去一条，它自己贡献的那一行就会消失（FR-4.2）。

## S-4 · 创作界面示意 `&step=create`

从首页点三次，**两种宽度都是**。FR-8.2 的上限是三次。

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 示意标注的上边缘 | 305 px | 492 px |
| 提示词 | 在平台的文本框里，10 行 | 同上 |
| 「生成」 | 距顶部 696 px，不可用 | 距顶部 426 px，不可用 |
| 打开时停在 | 页面顶部 | 示意标注处，距顶部 16 px |

**整个示意放得下时，页面在顶部打开；放不下时，在示意处打开**（`createScrollTop`）。最初测量时，页面总在顶部打开：在手机上，页面标题和陈述占去了前 492 px，「生成」因此位于 902 px，在 812 px 的首屏线以下，它的说明「不会生成任何音频」还要更靠下。现在页面打开时，示意标注位于 16 px，说明在 494 px 处结束。1280 × 820 下没有任何变化。在 1280 × 720 下，说明本会在 764 px 处结束，页面同样在示意处打开。标题和陈述在往上一屏的位置；读者进来时已经从它们旁边经过。

## S-5 · 公司视角 `/company`

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 容器，然后是栏 | 1024 px，然后是 672 px | 全宽 |
| 示意标注的上边缘 | 105 px | 147 px |
| 各区 | 商业论证 · 它会测量什么 · 它会怎样测试 · 五个部门会问什么 | 同上 |

**样本量是计算结果打印出来的，从不手工填写**（FR-9.3）：在规划基线（baseline）下每组 6,510 名访客，基线为 10% 时 3,841 名，30% 时 8,394 名。`prd-complete.test.ts` 会重新计算这三个数。

# 听辨测试

**2026-09-23 没有重新测量。** 按蓝图所做的修改没有改变这些界面（D3 修正案）。数字来自 2026-09-13 的测量，其中要紧的两个由测试守住，不依赖那个日期。

## S-6 · 一项测试的流程：`/bias`，名气偏差测试

五个界面：介绍、盲评一遍、过渡、带标签一遍、事后说明。

| | 1280 px | 375 px |
|---|---|---|
| 容器 | 1024 px | 375 px |
| 评分量表 | **11 个按钮，一行，每个 83 px** | 11 个按钮，两行，6 + 5，每个 51 px |

**量表排成几行，本身就是规格，算不上细节。** 量表一换行，看上去就像网格，不再像一条线：两端不再是两端，5 落在 0 的正下方。从 `lg` 断点起排成一行，以下排成六列，由 `src/app/bias/scale-row.test.ts` 对照量表自身的长度守住。

**每个评分界面的状态：**片段播放前锁定 · 播放后可选 · 已选 · 横跨两遍的进度条。片段没有听过，就无法评分。

## S-8 · 一个听辨结果

有意做窄：它是给人读的，行长比宽度更要紧。

**顺序，从上到下：**主数字 · 结论对 · 白话说明 · 创作者条目 · 校准区块 · 有第二次测试时的复测训练线 · 专家面板 · 分享卡片。数字下方的每个区块都可以拒绝给出：一次测试支撑不了某项结论时，界面会明说，并列出算式。

# 周边部分

## S-9 · `/lab`

| | 实测，2026-09-23 |
|---|---|
| 容器 | 1024 px |
| 各区 | 4 个：面板 · 指标词典 · 还没建成 · 漏斗，按规格写出 |
| 链接的面板页 | 5 |
| 数据来源徽标 | 先是四类徽标的图例，然后**另有 3 个，每个都是 `SIMULATED`**：两个在面板区，一个在漏斗上 |

**没有任何面板标着 `REAL`。** 分析流程是在真实答案已知的数据上验证的，每个面板都这样说明。页面上唯一的 `REAL` 徽标是图例里的说明项；某个面板一旦带有它，`site-badges.test.tsx` 就会失败。本部分的早先版本写的是「4 个面板，7 个徽标，每个都是 SIMULATED」：它把区当成了面板，把图例算成了徽标。
