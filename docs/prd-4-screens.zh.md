## 每个页面共用的框架

| | 实测 |
|---|---|
| 1280 px 下的容器 | **1024 px**（`max-w-5xl`），由 `src/app/shell-width.test.ts` 守住 |
| 375 px 下的容器 | 全宽，两侧各留 24 px 边距 |
| `/reading` 和 `/company` 上的阅读栏 | 1280 下为 672 px；375 下为 327 px |
| 无横向滚动 | 下面每个界面，在两种宽度下都没有 |

**框架共用，阅读栏不共用。** 曾经试过把正文加宽到 1024 px，后来撤回：加宽后的排版不如原先的窄栏。

# 解读

## S-1 · 首页 `/`

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 主标题 | 4 行 | 5 行 |
| 听者卡片 | 3 张，每行一张 | 3 张，每行一张 |
| 第一张卡片的上边缘 | 542 px | **684 px** |
| 听辨测试区 | 4 张测试卡片排成一行，后面是瑕疵链接 | 4 张测试卡片，每行一张 |

**访客在正文中第一个能操作的元素是一张听者卡片**（FR-8.2），两种宽度下它都在首屏之内。在 812 px 高的手机屏幕上，卡片从 684 px 处开始，首屏依次是主标题、引向解读的过渡句和一张卡片的顶部。页头放着公司视角、资料室、实验室和方法；页面自身的各区放着解读和听辨测试。

## S-2 · 解读 `/reading?l=…`

从首页点一次即可到达。以第一位听者 Mira 测量。

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 条目 | 4 | 4 |
| 第一条的上边缘 | 465 px | 700 px |
| 条目宽度 | 672 px | 327 px |

**每一条从上到下：**规律 · 依据 · 「展开播放记录」 · 两种提示读法和「都不对」 · 「这条不对」。

**每一条的状态：**保留（默认） · 删去，此时提示读法换成「已删去。它不会进入你的提示词。」和「放回来」 · 已选读法 · 播放记录展开或收起。页面关于自身用途的说明，位于标题下方、第一条上方（FR-8.3）。

## S-3 · 提示词 `&step=prompt`

从首页点两次即可到达。

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 提示词，尚未反驳 | 10 行，成块显示 | 10 行，宽 327 px，自动换行，不横向滚动 |
| 桥梁标记，全新浏览器 | 0 | 0 |
| 操作 | 「复制」 · 「用听辨测试校准这些词」 · 「贴进 Tessavox」 | 同上 |

**全新浏览器上不显示任何标记，这是规格要求的状态**（FR-6.2）：标记只来自设备上存储的阈值测试结果。选了某种读法之后，提示词里才会出现「情绪」一行（FR-4.3）；删去一条，它在提示词里贡献的那一行随之消失（FR-4.2）。

## S-4 · 创作界面示意 `&step=create`

**两种宽度下**，从首页都是点三次到达。FR-8.2 规定的上限正是三次。

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 示意标注的上边缘 | 305 px | 492 px |
| 提示词 | 在平台的文本框里，10 行 | 同上 |
| 「生成」 | 距顶部 696 px，处于禁用状态 | 距顶部 426 px，处于禁用状态 |
| 打开时停在 | 页面顶部 | 示意标注处，距顶部 16 px |

**整个示意能在一屏内放下时，页面从顶部打开；放不下时，直接停在示意处**（`createScrollTop`）。第一次测量时，页面总是从顶部打开。在手机上，页面标题和页面说明占去了前 492 px，「生成」因此落在 902 px 处，在 812 px 的首屏之下，它的附注「不会生成任何音频」还要更靠下。现在页面打开时，示意标注位于距顶部 16 px 处，附注在 494 px 处结束。1280 × 820 下的表现没有变化。在 1280 × 720 下，附注本会在 764 px 处结束，所以页面同样停在示意处。标题和页面说明就在上方一屏；读者进来的路上已经看过它们。

## S-5 · 公司视角 `/company`

| | 1280 × 820 | 375 × 812 |
|---|---|---|
| 容器与内容栏 | 容器 1024 px，内容栏 672 px | 全宽 |
| 示意标注的上边缘 | 105 px | 147 px |
| 各区 | 商业论证 · 它会测什么 · 它会怎样检验 · 五个部门会问什么 | 同上 |

**样本量直接显示计算结果，从不手工填写**（FR-9.3）：在规划基线（baseline）下每组 6,510 名访客，基线为 10% 时每组 3,841 名，30% 时每组 8,394 名。`prd-complete.test.ts` 会重新计算这三个数。

# 听辨测试

**2026-09-23 没有重新测量。** 按蓝图所做的修改没有改动这些界面（D3 修正案）。数字来自 2026-09-13 的测量；其中要紧的两个由测试守住，不依赖那次测量的日期。

## S-6 · 一项测试的流程：`/bias`，名气偏差测试（Prestige Test）

五个界面：介绍、盲评一轮、过渡、带标签一轮、事后说明（debrief）。

| | 1280 px | 375 px |
|---|---|---|
| 容器 | 1024 px | 375 px |
| 评分量表 | **11 个按钮，一行，每个 83 px** | 11 个按钮，分两行（6 + 5），每个 51 px |

**量表排成几行属于规格本身，谈不上细节。** 量表一换行，看上去就成了网格，不再是一条线：两端不再是两端，5 落在 0 的正下方。`lg` 断点及以上排成一行，以下排成六列；`src/app/bias/scale-row.test.ts` 依据量表自身的长度守住这一点。

**每个评分界面的状态：**片段播放前锁定 · 播放后可选 · 已选 · 横跨两轮的进度条。片段听完之前无法评分。

## S-7 · 其他测试

| 界面 | 容器 | 控件 | 为什么不用页面框架的宽度 |
|---|---|---|---|
| `/delicacy` | 512 px | 二选一，然后三选一的瑕疵命名 | 没有需要换行的内容；加宽只会把一项需要专注的任务拉散 |
| `/threshold` | 512 px | 每一级二选一 | 同上 |
| `/spread` 评分 | 1024 px | 11 点量表 | 与 S-6 同样的缺陷，同样的修法 |
| `/spread` 介绍和结尾 | 576 px | 正文 | 纯文字界面，行长才是关键 |

## S-8 · 听辨结果页

有意做窄：这一页是拿来读的，行长比宽度更要紧。

**从上到下的顺序：**主数字 · 成对的结论 · 白话说明 · 写给创作者的几行 · 校准区块 · 有第二次测试时的复测训练线 · 专家面板 · 分享卡片。数字下方的每个区块都可以拒绝给出结论：一次测试的数据撑不起某项解读时，界面会明说，并列出算式。

# 周边部分

## S-9 · `/lab`

| | 实测，2026-09-23 |
|---|---|
| 容器 | 1024 px |
| 各区 | 4 个：面板 · 指标词典 · 还没建成 · 漏斗，按规格写出 |
| 链接的面板页 | 5 |
| 数据来源徽标 | 先是四类徽标的图例，然后**另有 3 个，每个都是 `SIMULATED`**：两个在面板区，一个在漏斗上 |

**没有任何面板标着 `REAL`。** 分析流程是在真实答案已知的数据上验证的，每个面板都写明了这一点。页面上唯一的 `REAL` 徽标是图例中的一项；某个面板一旦带上它，`site-badges.test.tsx` 就会失败。本部分的早先版本写作「4 个面板，7 个徽标，每个都是 SIMULATED」：它把区当成了面板，把图例算成了徽标。

## S-10 · `/method`

| | 实测，2026-09-23 |
|---|---|
| 容器 | 1024 px，阅读栏宽 768 px |
| 各区 | 6 个，包括七项否决和三次改判两个区 |
| 否决 | **7 项**，每项标题都以「否决的理由：」开头 |

**推论标注（inference label）是这个页面必须满足的条件。** 页面凡是在重建推理、没有直接引用裁定的地方，都在读者的阅读路径上明说，不放进页脚。由 `src/app/method/inference-mark.test.ts` 固定。
