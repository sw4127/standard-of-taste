## Findings that must not be lost

These were measured, and each changed a decision. They are the project's
strongest interview material.

1. **The 6-trial pool could not support any psychometrics.** α = 0.25; *zero*
   items could clear the §1 discrimination floor; 2PL parameters pinned at
   their bounds. Three independent methods, one conclusion. Pool is now 18
   (α = 0.49 — still under the 0.70 floor; Spearman-Brown wants ~44).
2. **The §1 discrimination floor of 0.20 is unreachable for a 2AFC test.**
   Fixed by attenuation correction (`r / √reliability`) and by IRT, which
   estimates `a` directly (r = 0.86 vs the proxy's 0.76).
3. **`fMax` of 10 kHz made the lossy family measure 0.042 dB instead of 1.900.**
   Analysis now runs at 44.1 kHz / 16 kHz.
4. **Clipping is invisible post-normalisation** — two detectors failed. It is
   now checked pre-loudnorm, in `degrade`.
5. **The prestige instrument understates susceptibility by ~9.5%**, and the
   control-drift baseline is itself biased toward zero by the scale ceiling.
6. **Sampling error shrinks with n; bias does not.** Recruiting more people
   buys item statistics and buys nothing against instrument bias.

## PM user-testing findings (the most valuable input received)

Four real runs. Every one of these was a genuine defect:

- **d2 was 35% silence** and my dead-air gate passed it — I had implemented
  "no dead air" as *longest contiguous run*. Fixed with `quietFraction`.
- **The player forbade same-moment A/B comparison**, which is the only way to
  hear a small difference. Fixed by `AbCompare`.
- **B never played** — a per-frame `currentTime` resync kept it permanently
  re-seeking. Fixed.
- **Switching clicked** — toggling `.muted` is a step discontinuity. Fixed with
  a 12 ms Web Audio gain ramp.
- **The Prestige Test was a memory test.** Fixed by rotating the labeled pass
  and changing the question between passes.
- **Gold read as the brand**, so Prestige looked dominant. Fixed by neutral
  brand chrome + two-tap theme selection.

## The unanswered question

The PM asked **who this is for**, and it is still open. My position, for what it
is worth: an assessment-only product has no audience — experts do not need the
score and novices cannot produce one. The *training* framing is the answer, and
the practice block is the first thing built that serves it. Memo D4 already says
the paid tier is the training arc. **The product may be one instrument short,
not one audience short.**

This is a product decision and it outranks three more `/lab` panels.

## Standing rules that bit hardest this session

- **Never default to "leave it"** when a fix exists (`no-leave-it-defaults`).
- **A gate only the PM can discharge is debt** — make it computable
  (`human-gates-become-debt`).
- **Effective over complex** — the user must *see* it helping them make better
  AI music (`effective-over-complex`).
- Read the **rendered output**, not the source, when checking copy. Two rounds
  of JSX whitespace bugs reached the browser.
- The PM finds real defects by using the product. Ask them to.
