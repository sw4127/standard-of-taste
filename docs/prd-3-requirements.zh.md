# 解读

## FR-1 · 由播放记录算出的条目

| | |
|---|---|
| **服务于** | UC-1（有依据）、UC-2（假设）、UC-4（有依据） |
| **计算** | `src/engine/reading/patterns.ts` 中的 `allFacts`、`pickFacts`、`STRENGTH_FLOOR`、`MIN_LINES`、`MAX_LINES` |
| **组装** | `src/content/reading/reading.ts` 中的 `readingFor` |
| **播放记录来源** | `src/engine/reading/generate.ts` 中的 `generatePlays`、`DAYS` |

- **FR-1.1** 一份解读由两样东西算出：听者四周的播放记录，以及这些播放所出自的曲库。生成播放记录所用的习惯参数，解读从不读取，因为读了就等于照着标准答案作答。
- **FR-1.2** 有五种规律可以成为条目：收听在多大程度上集中于少数几首曲子；有多少收听发生在深夜；有多少是新曲；声音从第一周到第四周怎样漂移；新曲多快被放弃。后三种反映听者眼下正在找的音乐（UC-4，BP-CA1）。
- **FR-1.3** 每种规律都有一个强度，以同一段收听内部的基线（baseline）衡量。基线是均匀分布：在听过的曲子之间、在一天的各个时段之间，或在新曲与熟曲之间均匀分布。**强度决定显示哪些条目，本身从不显示。** 强度不涉及与其他听者的比较，因为并没有其他听者（N3）。
- **FR-1.4** 一份解读显示三到四条：凡强度达到下限的规律都显示，从强到弱，最多四条。达到下限的不足三种时，显示最强的三种。
- **FR-1.5** 同一位听者总是产生相同的播放记录和相同的条目，评审者因此可以核对依据，测试也可以重新计算。

**QA 边界情况。** 达到下限的规律不足三种 · 首次收听不足四次，新曲放弃速度这一规律因此没有强度 · 两种声音在保留下来的新曲数上并列最多，因此不点名任何一种声音 · 某位听者的播放只涉及不到三首不同的曲子。

## FR-2 · 依据

| | |
|---|---|
| **服务于** | UC-2（假设） |
| **代码** | `src/content/reading/lines.ts` 中的 `readingLine` |

- **FR-2.1** 每一条都附有依据：规律背后的计数（用文字写出），以及产生它的那些播放。
- **FR-2.2** 读者点「展开播放记录」时，这些播放在该条下方展开；如果该条统计的正是放弃次数，每次播放都会标明保留还是在 30 秒内放弃。
- **FR-2.3** 依据列出的正好是该规律计入的全部播放，从不抽样。这回应了巴纳姆效应（Barnum effect）式的质疑（BP-ARG-REPLY）：一条指向具体播放的条目，只对这段收听成立，并非对所有人都成立。

## FR-3 · 反驳一条：语气规则（register）

| | |
|---|---|
| **服务于** | UC-3（假设） |
| **代码** | `src/content/register.ts` 中的 `patternBreaches`、`offerBreaches`、`FEELING_WORDS` |
| **红线条款（carve-out）** | `src/content/carve-out.ts` 中的 `carveOutBreaches`、`CARVE_OUT_PATTERNS` |
| **第三个选项** | `src/content/reading/lines.ts` 中的 `NEITHER` |

- **FR-3.1** 每一条由三部分组成：规律、规律的依据，以及对其可能含义的两种提示读法。
- **FR-3.2** **规律不点出任何感受。** 它只说播放记录显示了什么：多少、何时、哪些。
- **FR-3.3** 每种提示读法都是一个问句。同一种规律可能出自相反的感受（BP-ARG-S1），所以提示两种，「都不对」始终是第三个选项。感受由读者补上；产品从不断言任何感受（BA-3）。
- **FR-3.4** 任何一条都可以删去，也可以放回。
- **FR-3.5** 任何模板、提示读法或提示词用词，都不对创伤、虐待或心理健康作任何断言（红线条款，RT-Z10 a，BA-5）。
- **FR-3.6** 没有任何一条把听者与他人比较：没有百分位，没有「大多数听者」之类的说法（N3）。

**QA 边界情况。** `lines.test.ts` 对三位听者的每一条运行全部检查，并用植入的违规样例证明每项检查确实拦得住 · 含有感受词的规律句 · 不以问号结尾的提示读法 · 每位听者的每种选择组合，都对照红线条款检查。

## FR-4 · 提示词

| | |
|---|---|
| **服务于** | UC-5（假设） |
| **计算** | `src/content/reading/prompt.ts` 中的 `buildPrompt`、`EMPTY_STATE`、`FAMILY_LABEL` |

- **FR-4.1** 提示词只由经过反驳后留下的内容组成。被删去的一条不贡献任何内容。
- **FR-4.2** 每一条保留的条目都贡献两样东西：它所涉曲子的声音，以及一个只属于它的方向，所以**删去任何一条都会改变提示词。** 第一版没有做到这一点：两条条目涉及同一种声音时，删去其中任何一条，提示词都可能纹丝不动。
- **FR-4.3** 选中的读法把它的用词加入提示词的情绪部分。选「都不对」或尚未选择时，不加入任何词。
- **FR-4.4** 声音按听辨测试测量的三类瑕疵分组（BP-BRIDGE）：音准（tuning）、节拍（timing）和保真度（fidelity）。自 2026-09-24 起，第三类称为保真度，不再称为动态范围：它测量以 kbps 计的编解码器（codec）损伤。
- **FR-4.5** 提示词使用通用的音乐生成工具词汇，不点名任何生成工具（RT-Z8 a）。
- **FR-4.6** 每一条都被删去时，提示词为空，界面会明说，不会只显示一个空白框。
- **FR-4.7** 提示词可以复制。没有剪贴板权限时，它仍是可以选中的文本。

**QA 边界情况。** 每一条都被删去 · 一种读法也没有选 · 每一条都选「都不对」 · 在同一条上先后选（a）和（b），两次必须得出不同的提示词。

# 听辨测试

按蓝图所做的这次修改没有改动四项测试（D3 修正案）。到达它们有两条路：从提示词经由桥梁（FR-6），或从 `/` 的听辨测试区。

## FR-11 · 名气偏差测试（Prestige Test）：不受偏见左右（freedom from prejudice）

| | |
|---|---|
| **服务于** | UC-8（假设） |
| **计算** | `src/engine/bias.ts` 中的 `computeBiasResult`、`BIAS_SCALE_MIN`、`BIAS_SCALE_MAX` |

- **FR-11.1** 一次测试把每个片段呈现两遍：一遍不附艺人名，一遍附上。带标签的那一遍换一种措辞提问，听者记住的上一个分数就答不上这个问题。
- **FR-11.2** 评分是固定量表上的整数。量表两端只由 `BIAS_SCALE_MIN` 和 `BIAS_SCALE_MAX` 定义；任何界面都不得另行写出两端的数值。
- **FR-11.3** 固定数量的片段在两遍里都不带标签。它们在两遍之间的变动属于漂移（记忆、均值回归、疲劳），要从带标签片段的变动中减去。
- **FR-11.4** 有些标签是假的。每一处欺骗都在无法跳过的事后说明（debrief）中披露。
- **FR-11.5** 结论是一个带正负号的百分比。负值表示评分朝远离标签的方向移动；这是另一种结果，谈不上更差。阈值：`BIAS_SWAYED_AT`、`BIAS_CONTRARIAN_AT`。
- **FR-11.6** 如果没有任何评分还有朝标签移动的余地，引擎拒绝给出结论，任何界面都不得显示结论。界面会说明这一点。

**QA 边界情况。** 盲评时每个片段都在量表最高端 · 每个片段都在最低端 · 零变动 · 只有对照片段有变动 · 带正负号的结果恰好为零。

## FR-12 · 细辨测试（Delicacy Trials）：鉴赏力（delicacy of taste）

| | |
|---|---|
| **服务于** | UC-6（假设） |
| **计算** | `src/engine/delicacy.ts` 中的 `computeDelicacyResult`、`detectionBand` |

- **FR-12.1** 每个试次是同一段音乐的两个版本，其中一个带有大小经过校准的损伤。听者先挑出原版，再说出瑕疵的名称。
- **FR-12.2** 练习试次显示答案，计分试次不显示，两者分开计数。
- **FR-12.3** 二选一时，单靠猜就能拿到一半的分数。结果报告经过机会校正的检出区间（detection band，`DELICACY_CHANCE`），**从不报告名次**。曾经做过六级排名档位，它把听者放入正确档位的比例只有 30.5%，于是被移除。
- **FR-12.4** 说出瑕疵名称这一项，以 `FLAW_CHANCE` 为随机水平计分，即瑕疵类别数的倒数，不以抛硬币的二分之一为准。
- **FR-12.5** 一次测试的数据撑不起按类别细分时，界面会明说，并列出算式。不得凭空编出细分结果。

**QA 边界情况。** 15 题答对 0 题 · 15 题答对 15 题 · 恰在随机水平 · 1 处里听出 1 处，此时英文的单数与复数共用同一句话 · 一次什么都没听出的测试，因而从未进入命名问题。

## FR-13 · 阈值阶梯（Threshold staircase）：鉴赏力的实测

| | |
|---|---|
| **服务于** | UC-6（假设） |
| **计算** | `src/engine/staircase.ts` 中的 `startStaircase`、`recordResponse`、`estimateThreshold` |

- **FR-13.1** 答对后损伤减小，答错后损伤增大，逐步收敛到听者仍能听出的最小水平。
- **FR-13.2** 结果以物理单位报告，即音分（cents）、毫秒和 kbps，**从不报告为分数**。
- **FR-13.3** 如果一次测试始终没能同时确定一个听出的水平和一个漏听的水平，结果会说明缺了哪一半，不用插值补上。
- **FR-13.4** 存储在设备上的结果，为解读提示词上的桥梁标记提供数据（FR-6）。

**QA 边界情况。** 每次都答对 · 每次都答错 · 在第一级就出现转折点（reversal） · 在阶梯任一端停止的测试。

## FR-14 · 排序测试（Ranking Test）：比较，凭耳朵

| | |
|---|---|
| **服务于** | UC-9（假设） |
| **计算** | `src/engine/spread.ts` 中的 `computeSpreadResult` |

- **FR-14.1** 一位评论家公开发表过这些作品的排名；听者盲评这些作品，看不到任何排名。
- **FR-14.2** 结果报告两个数字：在评论家拉开距离的作品对上，听者的评分相差多远；在评论家归为一组的作品对上，同一数字是多少。两者并列显示。
- **FR-14.3** **与评论家的一致程度从不计分，也无法计算。** 导入的只有评论家所排各位置之间的距离，从未导入这些位置的先后顺序。这个产品既然要测量一个响亮的名字能把听者左右到什么程度，就不能同时因为听者与一位有名的评论家意见一致而给分。这项拒绝只有一种措辞，写在 `src/content/critic-refusal.ts` 中；出现第二种写法，测试就会拦下。

## FR-15 · 信心校准：良好的判断力（good sense）

| | |
|---|---|
| **服务于** | UC-6（假设），作为对细辨测试作答的第二种分析 |
| **计算** | `src/engine/calibration.ts` 中的 `computeCalibration`、`BRIER_COIN_FLIP`、`MIN_BIN_N` |

- **FR-15.1** 细辨测试中每个计分的作答，都附带一个自报的信心，取值来自固定集合 `DELICACY_CONFIDENCE_LEVELS`。
- **FR-15.2** 以布里尔分数（Brier score）计分，对照 `BRIER_COIN_FLIP`；同时计算自报正确率与实际正确率之间的差距。
- **FR-15.3** 观测数少于 `MIN_BIN_N` 的分箱（bin）不以比率显示。这个下限是一个常量，并非每个界面各自作出的判断。

## FR-16 · 复测训练线（retest arc）：练习（practice）

| | |
|---|---|
| **服务于** | UC-10（假设） |
| **计算** | `src/engine/arc.ts` 中的 `ARC_FLOORS` |

- **FR-16.1** 同一设备上的第二次测试与第一次比较。
- **FR-16.2** 差异小于测试自身在两次运行之间的波动时，报告为**没有变化**，不算作进步。这个下限在编写比较逻辑之前就先测出。
- **FR-16.3** 「没有听得出的变化」这一结论必须能够出现，并且必须正确显示。大多数复测得到的都是它；它是诚实的答案，并非失败状态。

## FR-17 · 每个结果、每种瑕疵，都用文字说出

| | |
|---|---|
| **服务于** | UC-7（有依据）、UC-11（假设） |

| **资料室** | `src/content/learn.ts` 中的 `LEARN_PAGES`、`learnPage` |

- **FR-17.1** 每个听辨结果都以句子收尾，不会停在带单位的数字上；句子由固定模板生成。相同的结果产生相同的句子。
- **FR-17.2** 比较性的陈述只在同一个人内部作出：读者听得最准的瑕疵类别，对比听得最差的类别。刺激的设置是已知的，所以这是真实答案（ground truth），不需要任何群体对照。
- **FR-17.3** `/learn/flaws` 说明每类瑕疵叫什么、听起来是什么样；`/learn` 说明休谟的每条标准指什么、由哪项测试测量。

## 非目标

本节由 `/method` 上的七项否决、证伪记录和蓝图裁定（BA-1 至 BA-12）汇总而成，不在这里重新论证。

| 不做什么 | 理由（一句话） |
|---|---|
| 由模型撰写访客会读到的任何句子 | 只用模板（BA-10）；页面一旦接触模型客户端，`src/app/no-model-text.test.ts` 就会让编译失败 |
| 解读真实听者的账号 | 原型从不对外发布（BP-GOAL）；解读只在三位示例听者上运行（BA-8） |
| 任何示意界面上出现真实的艺人、曲子或品牌 | 每个名字都是虚构的，并经过核对（BA-8、BA-9） |
| 生成的音频 | 创作界面是带标注的示意（BA-11） |
| 告诉读者自己有什么感受的句子 | 同一种规律可能出自相反的感受（BA-3，BP-ARG-S1） |
| 请人描述自己品味的问题 | 几乎没有人做得到（BP-CA2）；提这类问题的小测验已经退役（BA-7） |
| 综合的品味指数 | 五种单位无法相互换算，合成需要一套权重，在 n = 0 时没有人能为任何权重给出理由 |
| 结果的五面画像 | 多数读者的多数面都是暗的，这样的画像只是一根完成度进度条 |
| 分级的结论档位 | 实测放对档位的比例只有 30.5%，已移除 |
| 付费层 | 已撤回；为训练循环收费，会把唯一诚实的问题挡在门外 |
| 人工听审片段 | 已改用声学测量，因为个人意见算不上题目证据（item evidence） |
| 任何与评论家一致程度的分数 | 用导入的数据算不出来，而且与 FR-11 矛盾 |
| 预置的用户群体 | 亲友规模的样本，比分析流程自身参数复原（parameter recovery）扫描中噪声最大的那一档还小 |
| 曲目推荐 | 需要有授权的曲库，音频规则禁止使用这类曲库 |
| 第五种测试工具，把偏好转成文字 | 估算需要 84 组配对、84 分钟，已放弃（RT-3 a）；即 `/method` 上的第七项否决 |
| 访客到达时的机器翻译 | 中文在编译之前写定并经过审阅；运行时不生成任何句子（BA-10） |

## 约束所有需求的前提条件

- **D1，限定范围。** 每个听辨结果都只针对这次的表现，从不评价这个人。D1 只在 `/reading` 上明文暂停（CLAUDE.md，D1 修正案中的第三个界面一节），在那里改由 BA-3 的语气规则管辖：一条只说出一种规律，并提示它可能意味着什么。
- **BA-10。** 访客读到的任何句子都不由模型撰写。
- **N3。** 没有群体对照，没有百分位，没有人与人之间的比较。实际参与者为零。
- **BP-GOAL。** 从不对外发布。每个模拟用户、每项指标、每位相关方，都在显示它的界面上有标注。
- **防同质化条款（anti-clone clause）**（CLAUDE.md，D4 修正案）。永远不做排行榜、经验值、连续打卡或积分。
- **音频。** 只用公有领域或知识共享（Creative Commons）许可的音频，损伤由本项目自己的信号处理制造，许可证明和源文件哈希由测试强制检查。
- **不声称迁移效果（transfer）。** 这些能否让一个人做出更好的作品，没有测量过，也不作此声称。
