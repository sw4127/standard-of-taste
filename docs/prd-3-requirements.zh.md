# 解读

## FR-1 · 由播放记录算出的条目

| | |
|---|---|
| **服务于** | UC-1（有依据）、UC-2（假设）、UC-4（有依据） |
| **计算** | `src/engine/reading/patterns.ts` 中的 `allFacts`、`pickFacts`、`STRENGTH_FLOOR`、`MIN_LINES`、`MAX_LINES` |
| **组装** | `src/content/reading/reading.ts` 中的 `readingFor` |
| **播放记录来源** | `src/engine/reading/generate.ts` 中的 `generatePlays`、`DAYS` |

- **FR-1.1** 一份解读由两样东西算出：听者四周的播放记录，以及这些播放所出自的曲库。生成这些播放的习惯参数，它从不读取：读了，就等于在读自己的答案。
- **FR-1.2** 有五种规律可以成为条目：收听在多大程度上堆在少数几首曲子上；多少收听发生在深夜；多少是新曲；声音从第一周到第四周怎样漂移；新曲多快被放弃。后三种是听者现在伸手去找的东西（UC-4，BP-CA1）。
- **FR-1.3** 每种规律有一个强度，以同一段收听内部的基线（baseline）衡量：在听过的曲子之间、在一天的各个时段之间、或在新曲和熟曲之间均匀分布。**强度决定显示哪些条目，强度本身从不显示。** 它并非与其他听者的比较，也没有其他听者可比（N3）。
- **FR-1.4** 一份解读显示三到四条：强度达到下限的每种规律，从强到弱，最多四条。达到下限的不足三种时，取最强的三种。
- **FR-1.5** 同一位听者总是产生同样的播放记录和同样的条目，所以评审者可以核对依据，测试也可以重新计算。

**QA 边界情况。** 达到下限的规律不足三种 · 首次收听不足四次，因而「放弃」这一规律没有强度 · 两种声音在保留下来的新曲数上并列最多，因而不点名任何一种声音 · 某位听者的播放只涉及不到三首不同的曲子。

## FR-2 · 依据

| | |
|---|---|
| **服务于** | UC-2（假设） |
| **代码** | `src/content/reading/lines.ts` 中的 `readingLine` |

- **FR-2.1** 每一条都带有依据：规律背后的计数（用文字写出），以及产生它的那些播放。
- **FR-2.2** 读者点开时，这些播放在条目下方展开（「展开播放记录」）；该条计的若是放弃，每次播放都标明保留了，还是在 30 秒内被放弃。
- **FR-2.3** 依据列出的正是该规律计入的全部播放，从不抽样。这是对巴纳姆效应（Barnum effect）这一质疑的回应（BP-ARG-REPLY）：一条指向具体播放的条目，只对这段收听成立，并非对所有人都成立。

## FR-3 · 反驳一条：措辞规范

| | |
|---|---|
| **服务于** | UC-3（假设） |
| **代码** | `src/content/register.ts` 中的 `patternBreaches`、`offerBreaches`、`FEELING_WORDS` |
| **红线条款** | `src/content/carve-out.ts` 中的 `carveOutBreaches`、`CARVE_OUT_PATTERNS` |
| **第三个选项** | `src/content/reading/lines.ts` 中的 `NEITHER` |

- **FR-3.1** 每一条有三部分：规律，它的依据，以及对它可能意味着什么的两种提示读法。
- **FR-3.2** **规律不点出任何感受。** 它只说播放记录显示了什么：多少、何时、哪些。
- **FR-3.3** 每种提示读法都是一个问句。同一种规律可能出自相反的感受（BP-ARG-S1），所以提示两种，「都不对」永远是第三个选项。感受由读者补上；产品从不断言某种感受（BA-3）。
- **FR-3.4** 任何一条都可以删去，也可以放回。
- **FR-3.5** 任何模板、提示读法或提示词里的词，都不对创伤、虐待或心理健康作任何断言（红线条款，RT-Z10 a，BA-5）。
- **FR-3.6** 没有一条把听者与任何人比较：没有百分位，没有「大多数听者」（N3）。

**QA 边界情况。** `lines.test.ts` 在全部三位听者的每一条上运行每项检查，并用植入的样例证明每项检查确实拦得住 · 含有感受词的规律句 · 不以问号结尾的提示读法 · 每位听者的每种选择组合，都对照红线条款检查。

## FR-4 · 提示词

| | |
|---|---|
| **服务于** | UC-5（假设） |
| **计算** | `src/content/reading/prompt.ts` 中的 `buildPrompt`、`EMPTY_STATE`、`FAMILY_LABEL` |

- **FR-4.1** 提示词只由经得住反驳的内容组成。被删去的一条什么也不贡献。
- **FR-4.2** 每一条保留下来的条目，贡献其曲子的声音和一个它自己的方向，所以**删去任何一条都会改变提示词。** 第一版违反了这一点：两条关于同一种声音的条目，删去其中一条，提示词可以纹丝不动。
- **FR-4.3** 选中的读法把它的词贡献给提示词的情绪部分。选了「都不对」，或者还没有选，就不贡献任何词。
- **FR-4.4** 声音按听辨测试测量的三类瑕疵分组：音准、节拍和保真度（BP-BRIDGE；自 2026-09-24 起，第三类称为保真度，不再称为动态范围，它测的是以 kbps 计的编解码（codec）损伤）。
- **FR-4.5** 提示词使用通用的生成工具词汇，不点名任何生成工具（RT-Z8 a）。
- **FR-4.6** 每一条都被删去时，提示词为空，界面会明说，不显示一个空白框。
- **FR-4.7** 提示词可以复制。没有剪贴板权限时，它仍是可以选中的文本。

**QA 边界情况。** 每一条都被删去 · 没有选任何读法 · 每种读法都选「都不对」 · 在同一条上先后选（a）和（b），两者必须得出不同的提示词。

# 听辨测试

四项测试没有因按蓝图所做的修改而改变（D3 修正案）。从提示词经由桥梁（FR-6）可以到达它们，从 `/` 的听辨测试区也可以。

## FR-11 · 名气偏差测试：不受偏见左右

| | |
|---|---|
| **服务于** | UC-8（假设） |
| **计算** | `src/engine/bias.ts` 中的 `computeBiasResult`、`BIAS_SCALE_MIN`、`BIAS_SCALE_MAX` |

- **FR-11.1** 一次测试把每个片段呈现两遍：一遍不附艺人，一遍附上艺人。带标签的那一遍换一种措辞提问，记住的数字就回答不了它。
- **FR-11.2** 评分是固定量表上的整数。`BIAS_SCALE_MIN` 和 `BIAS_SCALE_MAX` 是量表两端的唯一定义；任何界面都不得另行写出这两端。
- **FR-11.3** 固定数量的片段在两遍里都不带标签。它们在两遍之间的变动属于漂移（记忆、回归、疲劳），从带标签片段的变动里减去。
- **FR-11.4** 有些标签是假的。每一处欺骗都在一个无法跳过的事后说明（debrief）里披露。
- **FR-11.5** 结论是一个带正负号的百分比。负值表示评分朝远离标签的方向移动；这是另一种结果，谈不上更差。阈值：`BIAS_SWAYED_AT`、`BIAS_CONTRARIAN_AT`。
- **FR-11.6** 如果没有任何评分有朝标签移动的余地，引擎拒绝给出结论，任何界面都不得打印结论。界面会明说。

**QA 边界情况。** 盲评时每个片段都在量表最高端 · 每个都在最低端 · 零变动 · 只有对照片段变动 · 带正负号的结果恰为零。

## FR-12 · 细辨测试：鉴赏力

| | |
|---|---|
| **服务于** | UC-6（假设） |
| **计算** | `src/engine/delicacy.ts` 中的 `computeDelicacyResult`、`detectionBand` |

- **FR-12.1** 每个试次是同一段音乐的两个版本，其中一个带有大小经过校准的损伤。听者先挑出原版，再说出瑕疵的名称。
- **FR-12.2** 练习试次显示答案。计分试次不显示，两者分开计数。
- **FR-12.3** 二选一时，一半的分数靠猜就能拿到。结果报告经机会校正的检出区间（`DELICACY_CHANCE`），**从不报告名次**。曾经做过六级排名档位，把听者放对档位的比例只有 30.5%，于是移除了。
- **FR-12.4** 说出瑕疵名称这一项，以瑕疵类别数的倒数 `FLAW_CHANCE` 为随机水平计分，不以抛硬币的二分之一为准。
- **FR-12.5** 一次测试支撑不了按类别细分时，界面会明说，并列出算式。不得凭空编出细分。

**QA 边界情况。** 15 题对 0 题 · 15 题全对 · 恰在随机水平 · 1 处里听出 1 处，英文的单数和复数共用一句话 · 一次什么都没听出的测试，因而从未进入命名问题。

## FR-13 · 阈值阶梯：鉴赏力，实测

| | |
|---|---|
| **服务于** | UC-6（假设） |
| **计算** | `src/engine/staircase.ts` 中的 `startStaircase`、`recordResponse`、`estimateThreshold` |

- **FR-13.1** 答对后损伤减小，答错后损伤增大，逐步收敛到听者仍然听得出的最小水平。
- **FR-13.2** 结果以物理单位报告，即音分（cents）、毫秒和 kbps，**从不报告为分数**。
- **FR-13.3** 一次测试没能同时确定一个听出的水平和一个漏掉的水平时，结果会说明缺了哪一半，不靠插值补出。
- **FR-13.4** 存储在设备上的结果，为解读提示词上的桥梁标记提供依据（FR-6）。

**QA 边界情况。** 每次都答对 · 每次都答错 · 在第一级就出现转折点（reversal） · 在阶梯任一端停下的测试。

## FR-14 · 排序测试：比较，靠耳朵

| | |
|---|---|
| **服务于** | UC-9（假设） |
| **计算** | `src/engine/spread.ts` 中的 `computeSpreadResult` |

- **FR-14.1** 一位发表过排名的评论家排过序的作品，在不显示任何排名的情况下盲评。
- **FR-14.2** 结果报告：在评论家拉开距离的作品对上，听者的评分相距多远；旁边列出在评论家归为一组的作品对上的同一数字。
- **FR-14.3** **与评论家的一致程度从不计分，也无法计算。** 导入的只有他各个位置之间的距离，从未导入这些位置的顺序。这个产品测量的是有名的名字能把听者左右到什么程度，就不能同时因为听者与有名的评论家意见一致而给分。这条拒绝只有一种措辞，写在 `src/content/critic-refusal.ts` 里，出现第二种写法，测试就会拒绝。

## FR-15 · 信心校准：良好的判断力

| | |
|---|---|
| **服务于** | UC-6（假设），作为对细辨测试作答的第二种分析 |
| **计算** | `src/engine/calibration.ts` 中的 `computeCalibration`、`BRIER_COIN_FLIP`、`MIN_BIN_N` |

- **FR-15.1** 细辨测试每个计分的回答，都带一个自报的信心，取自固定的集合 `DELICACY_CONFIDENCE_LEVELS`。

## FR-16 · 复测训练线：练习

| | |
|---|---|
| **服务于** | UC-10（假设） |
| **计算** | `src/engine/arc.ts` 中的 `ARC_FLOORS` |

- **FR-16.1** 同一设备上的第二次测试与第一次比较。
- **FR-16.2** 差异小于测试自身两次运行之间的波动，就报告为**没有变化**，不算作进步。这个下限在写比较之前先测出。
- **FR-16.3** 「没有听得出的变化」必须能够出现，并且必须正确显示。大多数复测的结果都是它；它是诚实的答案，并非失败状态。

## FR-17 · 每个结果、每种瑕疵，都用文字说出

| | |
|---|---|
| **服务于** | UC-7（有依据）、UC-11（假设） |
| **代码** | `src/content/vocabulary/`，逐条列在 `docs/copy-deck.md` |
| **资料室** | `src/content/learn.ts` 中的 `LEARN_PAGES`、`learnPage` |

- **FR-17.1** 每个听辨结果的结尾都是句子，光有单位不够；句子由固定模板生成。相同的结果产生相同的句子。
- **FR-17.2** 比较性的陈述只在一个人之内：读者最敏锐的瑕疵类别对比最迟钝的。这是由已知刺激设置得出的真实答案（ground truth），不需要任何群体对照。
- **FR-17.3** `/learn/flaws` 说明每类瑕疵叫什么、听起来什么样；`/learn` 说明休谟的每条标准是什么意思、由哪个测试测量。

## 非目标

由 `/method` 上的七项否决、证伪记录和蓝图裁定（BA-1 至 BA-12）汇总而成，不在这里重新论证。

| 不做的东西 | 理由，一句话 |
|---|---|
| 由模型写任何访客会读到的句子 | 只用模板（BA-10）；页面一旦接触模型客户端，`src/app/no-model-text.test.ts` 就会失败，版本无法发布 |
| 解读真实听者的账号 | 原型不对外发布（BP-GOAL）；解读只在三位示例听者上运行（BA-8） |
| 任何示意界面上出现真实的艺人、曲子或品牌 | 每个名字都是虚构的，并经过核对（BA-8、BA-9） |
| 生成的音频 | 创作界面是有标注的示意（BA-11） |
| 告诉读者有什么感受的句子 | 同一种规律可能出自相反的感受（BA-3，BP-ARG-S1） |
| 请人描述自己品味的问题 | 几乎没有人做得到（BP-CA2）；问这些问题的小测验已经退役（BA-7） |
| 综合的品味指数 | 五种无法相互换算的单位需要一套权重，在 n = 0 时没有人能为任何权重给出理由 |
| 结果的五面画像 | 对大多数读者来说多数面都是暗的，画像就成了完成度进度条 |
| 分级的结论档位 | 实测放对档位的比例只有 30.5%，已移除 |
| 付费层 | 已撤回；为训练循环收费，会把唯一诚实的问题挡在墙后 |
| 人工听审片段 | 已由声学测量取代，因为个人意见算不上题目证据 |
| 任何与评论家一致程度的分数 | 用导入的数据算不出来，而且与 FR-11 矛盾 |
| 预置的用户群体 | 朋友圈规模的样本，落在分析流程自身参数复原（parameter recovery）扫描中噪声最大那一端的下方 |
| 曲目推荐 | 需要一个有授权的曲库，音频规则禁止这样做 |
| 第五种测试工具，把偏好转成文字 | 估算需要 84 组配对、84 分钟，已否决（RT-3 a）；`/method` 的第七项否决 |
| 访客到达时的机器翻译 | 中文在上线之前写好并经过审阅；运行时不生成任何句子（BA-10） |

## 约束每一条需求的前提

- **D1，限定范围。** 每个听辨结果都只关于表现，从不关于这个人。D1 只在 `/reading` 上按名称暂停（CLAUDE.md「D1 修正案，第三个界面」），在那里由 BA-3 的措辞规范管辖：一条只说出一种规律，并提示它可能意味着什么。
- **BA-10。** 访客读到的任何句子，都不由模型写。
- **N3。** 没有群体对照，没有百分位，没有人与人之间的比较。答题者为零。
- **BP-GOAL。** 从不对外发布。每个模拟用户、每项指标、每位相关方，都在显示它的界面上有标注。
- **反模仿条款**（CLAUDE.md，D4 修正案）。永远没有排行榜、经验值、连续打卡或积分。
- **音频。** 只用公有领域或知识共享（Creative Commons）许可的音频，由本项目自己的信号处理制造损伤，许可证明和源文件哈希由测试强制检查。
- **不声称迁移效果。** 这些东西能否让一个人做出更好的作品，没有测量过，也不作声称。
