## FINDINGS THAT MUST NOT BE LOST

1. **THE COMPRESSION LADDER SUPPORTS ONE BAND. It can say a threshold and nothing about how
   finely it was heard.** Pitch and timing support two. I shipped `CARD_BANDS` as a guess of
   2/2/2 *before* measuring and the first run refuted it. `docs/analytics/e21-card-bands.txt`.
   Any future copy implying a fineness comparison on compression is false.
2. **"NOT ENOUGH TO TELL" IS THE CARD'S COMMON OUTPUT, NOT ITS EDGE CASE.** Across listeners
   drawn over a ladder's whole range, a point estimate comes back in **80%** of pitch sittings,
   **30%** of timing, and **16%** on one compression source. A listener at the floor or ceiling
   cannot be bracketed and the instrument says so. The card is built for that answer.
3. **A TEST WRITTEN RELATIVE TO ITS OWN CONSTANT CANNOT DETECT THAT CONSTANT BEING ZEROED.**
   My sample-floor specimen was `MIN_REPEAT_N - 1`, so setting the floor to 0 moved the
   specimen with it and the test passed with the guard switched off. This is the scale-free
   vacuity `arc-resolution.test.ts` documents catching in its own criterion (iii) — reproduced
   one file later. **Specimens must be absolute numbers.**
4. **`bandFor` READ THE COMPRESSION LADDER BACKWARDS AND NOTHING COULD SEE IT.** Rungs there
   are bitrates and the ladder runs *downward*: 32 kbps is the harshest damage and the coarser
   ear. Ordering by the smaller number called that ear *fine*. It was invisible through
   `bandFor` because compression has one band, so every index is 0 either way. **A defect that
   only appears when a measurement improves is the worst kind to leave in** — fixed by
   extracting `bandIndexIn` and exercising a two-band down ladder directly.
5. **THE CARD AND THE SCREEN DESCRIBED ONE SITTING WITH TWO DIFFERENT NUMBERS.** The card said
   "7.5 cents" directly above a headline reading "12.5 cents" — the fitted threshold and the
   rung actually caught, both true, irreconcilable to anyone looking at them together. Found
   by reading the rendered page. `thresholdCardFigure` is the product's one canonical figure
   and every surface must take it.
6. **`tsc` CAUGHT WHAT THE GREEN RUN COULD NOT.** My own fixtures called a four-argument helper
   with three; the observer was built at `magnitudes[undefined]` and every assertion passed
   against a degenerate session. Vitest does not typecheck. **A green suite is not the
   evidence on its own.**
7. **THE CLIPBOARD API'S FAILURE PATH IS THE COMMON ONE.** `writeText` rejects with
   `NotAllowedError` whenever the document is unfocused — every embedded preview, every
   automated run, any tab the reader clicked away from. The first handler swallowed it
   silently. It now selects the text and relabels the button.
8. **THE `RT-Z` ID NAMESPACE WAS ALREADY EXHAUSTED.** RT-Z2, Z6, Z7, Z8 and Z9 each carried an
   unrelated earlier answer before this session reissued them. Rulings are **date-qualified**
   from here; the collision table is §0 of `docs/rt-answers-2026-09-16.md`.
9. **FORTY MINUTES WENT INTO A 404 THAT WAS A STALE `.next` CACHE.** `/threshold/<slug>/result`
   returned 404 for a valid payload while the same code path rendered fine in Node. `rm -rf
   .next` fixed it. I nearly filed it as a SHIP-RISK about broken share permalinks.
